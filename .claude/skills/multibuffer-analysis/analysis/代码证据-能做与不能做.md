# MultiBuffer 能做与不能做：代码证据

## 总览：Pattern 注册入口

所有标记逻辑的入口在 `MarkMultiBufferPass::runOnOperation()`（[MarkMultiBuffer.cpp#L265-L322](file:///home/zk/bishengir-compile/AscendNPU-IR-Dev/bishengir/lib/Dialect/HIVM/Transforms/MarkMultiBuffer.cpp#L265-L322)）。四种场景通过三个维度决定是否注册：

```cpp
// === 维度1: Cube 组（标量搬运） ===
const bool allowCubeGroup =
    !isMixFuncCore ||
    !(limitMixAutoMultiBufferBuffer == MultiBufferStrategy::ONLY_VECTOR);

if (allowCubeGroup) {
    // 输入端: GM → L1 cbuf
    if (!disableMultiBufferOnL1)
        patterns.insert<MarkMultiBuffer<hivm::ND2NZOp>>(...);       // → 3.2
    // 输出端: L0C → UB/GM — 默认 CUBE_NO_L0C 禁用
    if (limitAutoMultiBufferOfLocalBuffer != CUBE_NO_L0C
        && !disableMultiBufferOnL0C)
        patterns.insert<MarkMultiBuffer<hivm::FixpipeOp>>(...);     // → 默认不注册
}

// === 维度2: Vector 组（矢标量搬运） ===
const bool allowVectorGroup =
    !isMixFuncCore ||
    !(limitMixAutoMultiBufferBuffer == MultiBufferStrategy::ONLY_CUBE);

if (allowVectorGroup && !disableMultiBufferOnUB) {
    patterns.insert<MarkMultiBuffer<hivm::LoadOp>>(...);            // → 3.1
    patterns.insert<MarkMultiBuffer<hivm::StoreOp>>(...);           // → 3.1
}

// === 维度3: Workspace（仅 MIX 核） ===
if (!limitAutoMultiBufferOnlyForLocalBuffer && isMixFuncCore)
    patterns.insert<MarkWorkspaceMultiBuffer<StoreOp>,
                    MarkWorkspaceMultiBuffer<FixpipeOp>>(...);       // → 3.3
```

**三种默认场景**（3.1 / 3.2 / 3.3）覆盖了 `runOnOperation()` 中默认开启的全部注册路径：

| 场景 | 核心 op | 搬运方向 | buffer 空间 | Pattern 类 |
|------|---------|----------|-------------|-----------|
| 3.1 Vector | Load / Store | GM ↔ UB | UB | `MarkMultiBuffer` |
| 3.2 Cube 输入 | ND2NZ | GM → L1 | L1 cbuf | `MarkMultiBuffer` |
| 3.3 Workspace | Store / Fixpipe | 写入 workspace | GM | `MarkWorkspaceMultiBuffer` |

Fixpipe（L0C→UB/GM）默认被 `CUBE_NO_L0C` 策略排除，Scope Preload（3.3）需要 CVPipeline Skew 模式才生效。

### 3.2 Cube 输入端 — ND2NZ（GM → L1 cbuf）

**注册证据**：[MarkMultiBuffer.cpp#L297-L300](file:///home/zk/bishengir-compile/AscendNPU-IR-Dev/bishengir/lib/Dialect/HIVM/Transforms/MarkMultiBuffer.cpp#L297-L300)
```cpp
if (allowCubeGroup) {
    if (!disableMultiBufferOnL1)
        patterns.insert<MarkMultiBuffer<hivm::ND2NZOp>>(patterns.getContext());
```

Cube 端只有**输入端**默认注册——ND2NZ 从 GM 搬运数据到 L1 cbuf，dst 非 GM，触发 `markBufferFunc(dst)` 标记 L1 buffer。

**输出端（Fixpipe，L0C → UB/GM）默认不注册**，被 `CUBE_NO_L0C` 策略排除：

```cpp
// L300-L304: Fixpipe 注册条件 — 默认 CUBE_NO_L0C 使条件为 false
if (limitAutoMultiBufferOfLocalBuffer != MultiBufferStrategy::CUBE_NO_L0C &&
    !disableMultiBufferOnL0C) {
    patterns.insert<MarkMultiBuffer<hivm::FixpipeOp>>(...);  // 默认不执行
}
```

Fixpipe 的 `getSrc()` 是 L0C 累加器，进入 `markBufferFunc` 会尝试标记 L0C buffer，但 L0C 有跨迭代 RAW 真依赖不适合 multibuffer，所以默认禁用。设 `--limit-auto-multi-buffer-of-local-buffer=no-limit` 可强制放开。

### 3.3 Workspace — MIX 核 Fusion Junction 缓冲

#### 3.3.1 什么是 Workspace

Workspace 是 kernel 级预分配的 GM scratchpad buffer，由 host/runtime 在 kernel 启动前创建，作为函数参数传入：

```mlir
%arg1: memref<?xi8> {hacc.arg_type = #hacc.arg_type<workspace>}
```

Kernel 内部通过 `memref_ext.alloc_workspace()` 从 workspace 参数中切出带类型的子 buffer：

```mlir
%5 = memref_ext.alloc_workspace() from %arg1 : from memref<?xi8> to memref<16x16xf32>
```

**Op 定义**：[MemRefExtOps.td#L31-L47](file:///home/zk/bishengir-compile/AscendNPU-IR-Dev/bishengir/include/bishengir/Dialect/MemRefExt/IR/MemRefExtOps.td#L31-L47)

#### 3.3.2 为什么需要 Workspace

Fixpipe 可以将数据直接从 L0C 写到 UB（Ascend950 系列），不需要经过 GM。Workspace 解决的是 **fusion 边界的中间结果物理内存缺失**问题。

`InsertWorkSpaceForMixCV.cpp:57-61` 匹配四种 cross-core junction 模式并插入 workspace：

```
CC: mmadL1 → fixpipe → load → mmadL1
CV: mmadL1 → fixpipe → load → vector
VC: vector → store → load → mmadL1
VV: vector → store → load → vector
```

核心逻辑（[InsertWorkSpaceForMixCV.cpp#L80-L101](file:///home/zk/bishengir-compile/AscendNPU-IR-Dev/bishengir/lib/Dialect/HIVM/Transforms/InsertWorkSpaceForMixCV.cpp#L80-L101)）：当 producer（store/fixpipe）的 dst 是 `tensor.empty`（无物理内存）时，用 workspace 替换它：

```
需要 workspace 的场景:
  [sub-graph A] → fixpipe(dst=tensor.empty) → load → [sub-graph B]
                       ↓ 替换
  [sub-graph A] → fixpipe(dst=workspace on GM) → load → [sub-graph B]
```

#### 3.3.3 MarkWorkspaceMultiBuffer 标记流程

与 3.1/3.2 的 `MarkMultiBuffer` 是**完全独立的 pattern 类**：

| 维度 | MarkMultiBuffer (3.1/3.2) | MarkWorkspaceMultiBuffer (3.3) |
|------|---------------------------|-------------------------------|
| 内存空间 | UB / L1 (片上) | GM (片外 workspace) |
| buffer 来源 | `memref.alloca()` | `memref_ext.alloc_workspace()` |
| 追溯函数 | `tracebackMemRef` → `isAllocLikeOp` | `tracebackForWorkspace` |
| 匹配入口 | Load/Store/ND2NZ 的 src/dst | Store/Fixpipe 的 **dst** (写入端) |
| 语义态 | `hasPureBufferSemantics()` | `hasPureTensorSemantics()` |

**tracebackForWorkspace**（[MarkMultiBuffer.cpp#L55-L70](file:///home/zk/bishengir-compile/AscendNPU-IR-Dev/bishengir/lib/Dialect/HIVM/Transforms/MarkMultiBuffer.cpp#L55-L70)）：
```cpp
FailureOr<Operation *> tracebackForWorkspace(Value val) {
    if (isa<BlockArgument>(val)) return failure();
    return TypeSwitch<Operation *, FailureOr<Operation *>>(val.getDefiningOp())
        .Case<bishengir::memref_ext::AllocWorkspaceOp>(  // ← 终点
            [&](auto op) { return op; })
        .Case<bufferization::ToTensorOp>([&](auto op) {
            return tracebackForWorkspace(op.getMemref());  // 穿透 to_tensor
        })
        .Case<mlir::ViewLikeOpInterface>([&](auto op) {
            return tracebackForWorkspace(op.getViewSource());  // 穿透 view/subview
        })
        .Default([&](auto op) { return failure(); });
}
```

**注册证据**：[MarkMultiBuffer.cpp#L315-L318](file:///home/zk/bishengir-compile/AscendNPU-IR-Dev/bishengir/lib/Dialect/HIVM/Transforms/MarkMultiBuffer.cpp#L315-L318)

    patterns.insert<MarkWorkspaceMultiBuffer<hivm::StoreOp>,

**标记条件**（[MarkMultiBuffer.cpp#L233-L258](file:///home/zk/bishengir-compile/AscendNPU-IR-Dev/bishengir/lib/Dialect/HIVM/Transforms/MarkMultiBuffer.cpp#L233-L258)）：

## 4. 需注意的非默认场景

### 4.1 Scope Preload（仅在 CVPipeline Skew 模式下生效）

> MarkMultiBuffer 运行**两次**：第一次在 CVPipelining 之前（pre-bufferization），此时 scope 上还没有 `preload_num`，`MarkScopeMultiBuffer` 全部返回 failure。第二次在 CVPipelining 之后（post-bufferization），`preload_num` 已被写入，才能触发标记。
>
> `preload_num` 由 CVPipelining 内部 `createNewLoopsForPreloadWithScopes()` 写入（`CVPipelining.cpp:1566`），`--enable-preload=true` 是强制 Skew 模式的向后兼容别名。
>
> 标记为 `multi_buffer = 4` + `preload_local_buffer = 1`，后续由 CreatePreload 拆分为 `scf.if` guard + EnableMultiBuffer 做 round-robin。

相关文件：[MarkMultiBuffer.cpp#L105-L155](file:///home/zk/bishengir-compile/AscendNPU-IR-Dev/bishengir/lib/Dialect/HIVM/Transforms/MarkMultiBuffer.cpp#L105-L155) | [CVPipelining.cpp#L1534-L1650](file:///home/zk/bishengir-compile/AscendNPU-IR-Dev/bishengir/lib/Dialect/HIVM/Transforms/CVPipelining.cpp#L1534-L1650) | [CreatePreload.cpp](file:///home/zk/bishengir-compile/AscendNPU-IR-Dev/bishengir/lib/Dialect/HIVM/Transforms/CreatePreload.cpp)

### 4.2 嵌套循环 yield 传递

**`getParentLoop()` 递归追踪 yield**（[EnableMultiBuffer.cpp#L54-L148](file:///home/zk/bishengir-compile/AscendNPU-IR-Dev/bishengir/lib/Dialect/HIVM/Transforms/EnableMultiBuffer.cpp#L54-L148)）：

当 buffer 被 `scf.yield` 或 `scf.if` 的 yield 传出当前循环体时，`getParentLoop` 会追踪 yield → loop result → user，穿越嵌套循环和条件分支，找到真正消费 buffer 的循环作为轮转锚点。

**`scf.while` 支持**（[MarkMultiBuffer.cpp#L185-L192](file:///home/zk/bishengir-compile/AscendNPU-IR-Dev/bishengir/lib/Dialect/HIVM/Transforms/MarkMultiBuffer.cpp#L185-L192)）：`scf.while` 和 `scf.for` 同等支持，依赖 alloca-based 迭代计数器统一处理，不修改循环签名。

## 5. 不能做的场景

### 5.1 L0C 空间 buffer（Cube 累加器）

`#hivm.address_space<cc>` 是 Cube 矩阵累加器，`mmadL1` 的结果跨迭代 RAW 真依赖，multibuffer 会破坏正确性。

**双重保护**：
1. Fixpipe 注册被 `CUBE_NO_L0C` 默认禁用（[MarkMultiBuffer.cpp#L301-L304](file:///home/zk/bishengir-compile/AscendNPU-IR-Dev/bishengir/lib/Dialect/HIVM/Transforms/MarkMultiBuffer.cpp#L301-L304)）
2. L0C buffer 不会被 Load/Store 使用（Load/Store 操作 UB↔GM），`tracebackMemRef` 找到 L0C alloc 后也不会命中 CopyLike 匹配

### 5.2 不在循环内的 buffer

`markBufferFunc` 中（[MarkMultiBuffer.cpp#L174-L177](file:///home/zk/bishengir-compile/AscendNPU-IR-Dev/bishengir/lib/Dialect/HIVM/Transforms/MarkMultiBuffer.cpp#L174-L177)）：
```cpp
auto parentLoop = mlir::hivm::getParentLoop(allocOp->getResult(0));
if (!parentLoop) return failure();  // 无 parent loop → 跳过
```
multibuffer 的核心是跨迭代轮转，buffer 必须在循环内。

### 5.3 不支持的循环类型

[MarkMultiBuffer.cpp#L185-L192](file:///home/zk/bishengir-compile/AscendNPU-IR-Dev/bishengir/lib/Dialect/HIVM/Transforms/MarkMultiBuffer.cpp#L185-L192)：
```cpp
while (parentLoop) {
    if (!isa<scf::ForOp, scf::WhileOp>(parentLoop)) {

```
`scf.parallel`、`scf.forall` 等不支持，因为它们的语义破坏 per-iteration slot rotation 不变式。
